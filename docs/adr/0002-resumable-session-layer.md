# ADR-0002 · 在 QUIC 之上再加一层可恢复会话层

- 状态：**已接受**
- 日期：2026-09-12

## 背景

容易产生的误解是："QUIC 有连接迁移，所以换网/断网都解决了"。

实际上 RFC 9000 的迁移能力边界是：**同一条存活的 QUIC 连接**换了地址仍可继续。
它不覆盖：

- 连接因 idle timeout 或长时间不可达而**死亡**（断网 40 秒，默认 idle timeout 远小于此）；
- 对端网络栈/容器重建导致的连接重置；
- 需要重新 Dial 的一切场景（此时 QUIC 给你一条**新连接**，旧的流状态全丢）。

如果只靠 QUIC，"断网几十秒"仍然会让 SSH 断开——这恰好是用户最痛的场景。

## 决策

引入独立的 Session 层，职责边界写死为：

```
QUIC         = IP/Port migration + NAT rebinding + path validation + 加密 + 拥塞控制
Session 层   = session_id + 绝对偏移量 + replay + 去重 + 跨连接重连 + 逻辑流多路复用
SSH          = 认证 + 加密 + channel 语义
```

关键设计选择：**用绝对字节偏移量而不是序列号 + 去重表**。
因为 Link 本身（QUIC 流）保证有序可靠，Session 层只需在重连点做一次对齐：
对端汇报 `recv_offset`，本端把发送游标回拨到该位置重放。偏移量天然幂等，
省掉了去重表、乱序重排缓冲和 ack 位图——这是本方案相对"自己造一个传输协议"的最大简化。

## 代价

- 需要保留未 ACK 数据的重放缓冲区（内存上界见 `03-session-resumption.md` §5）；
- 多一层拷贝与帧头开销（帧头 ≤ 约 20 字节 / ≤64 KiB 分片，可忽略）；
- 双层流控（QUIC 的 + 我们的）需要窗口配置协调，否则吞吐受限于较小者。

## 替代方案

- **只靠 QUIC + 让 SSH 断开**：否决，丢掉核心卖点。
- **靠 QUIC 0-RTT 恢复**：0-RTT 只省握手 RTT，不恢复流状态，且有重放攻击面。列入 M5 评估。
- **复刻 mosh 的 SSP（状态同步协议）**：那是终端语义层的幂等同步，无法透明承载 `scp`、
  端口转发这类任意字节流。否决。
